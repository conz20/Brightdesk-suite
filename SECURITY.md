# Security Policy

## Supported versions

Security fixes are developed against the current supported Brightdesk Office Suite release and the repository's `main` branch. Older releases may not receive fixes unless the release notes say otherwise.

## Reporting a vulnerability

**Do not publish vulnerability details, exploit code, credentials, private data or proof-of-concept material in a public issue, pull request or discussion.**

Use GitHub's private vulnerability reporting form at https://github.com/conz20/Brightdesk-suite/security/advisories/new when the feature is enabled for this repository. Private reports are available only after the repository owner enables the feature in GitHub Settings. If the form is unavailable, open a general issue asking for the preferred private security contact, but include no vulnerability details until a private channel is confirmed.

Include only the minimum information needed to help reproduce and assess a suspected issue. Allow maintainers a reasonable opportunity to investigate and prepare a fix before public disclosure.

## Scope

This policy covers security issues in Brightdesk Office Suite source, product integration, build and release workflows, dependencies and published artifacts. Third-party dependencies should also be reported to their respective maintainers using the contact method published by those projects.
