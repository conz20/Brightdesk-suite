# Brightdesk visual identity

Date: 2026-11-03

## Identity direction

Brightdesk should feel like a calm, capable desktop workspace: precise, clear, modern and welcoming. Its identity is built around layered document panels that form a forward-moving B. This is original Brightdesk artwork, not a redraw of another company's logo.

## Core palette

| Token | Value | Use |
| --- | --- | --- |
| Midnight | #101827 | App chrome and deep surfaces |
| Navy | #152A52 | Primary brand surface |
| Teal | #36A8B8 | Primary action and selected state |
| Mint | #70E1D1 | Accent and positive state |
| Periwinkle | #667FE0 | Secondary accent |
| Paper | #F5FBFF | Light surfaces and contrast |
| Ink | #17243A | Main text on light surfaces |

Use semantic tokens for success, warning, danger and disabled states rather than using accent colours decoratively.

## Layout and interaction principles

- Keep a stable left navigation rail and a clear working canvas.
- Use consistent spacing, predictable toolbars and visible keyboard focus.
- Prefer readable labels and familiar office workflows over icon-only controls.
- Support light and dark themes without changing the product identity.
- Keep app-specific colour accents subtle; the suite mark remains consistent.
- Make status visible in words: Available, Installed, Update available or Planned.
- Use original line icons and app artwork; never reuse Storytold or Microsoft icons.

## Typography

Use platform UI fonts with a clear sans-serif fallback stack. Maintain readable body text, restrained heading weights and strong contrast. Do not embed third-party fonts unless their licence and attribution are reviewed.

## App icon family

Each of the ten approved apps receives an original icon built from a shared rounded-square container and consistent geometry. The central glyph should communicate the app's purpose; app accents distinguish tools without changing the family identity. The suite mark is at assets/branding/brightdesk-suite-mark.svg.

## Ownership

Brightdesk names, logo, artwork, UI and visual tokens are independent. Similarity is limited to common productivity conventions such as a toolbar, navigation rail, ribbon-like command grouping and document canvas.
